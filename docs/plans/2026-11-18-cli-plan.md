# The `ryo2d` Command Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ryo2d` becomes its own crate with one argument parser, honest exit codes, prompts that never act without a person, one way to find what cargo built, templates proven to build, and an export that runs on Mac and Linux.

**Architecture:** Move `src/cli/` and `src/bin/ryo2d.rs` into `crates/ryo2d-cli` (package `ryo2d-cli`, binary `ryo2d`) depending on `ryo2d`; replace hand parsing with clap derive; route every prompt through one `Prompt` helper; ask cargo (`cargo metadata`, JSON build messages) instead of guessing paths.

**Tech Stack:** Rust, clap 4 (derive), thiserror 2, zip 2, serde_json, cargo.

**Spec:** `docs/specs/2026-11-18-cli-design.md`

## Global Constraints

- Exit codes: 0 success; 1 the CLI failed; 2 bad arguments (clap's); `run` and `dev` pass the game's own non-zero code through.
- With no terminal on stdin a prompt changes nothing and says which flag would; end of file is "no".
- The CLI never sets `CARGO_TARGET_DIR`; the target folder comes from `cargo metadata --format-version 1 --no-deps`.
- clap: the version already in `Cargo.lock` (4.6.x), features `derive`. No other new dependency.
- Output style unchanged (`Output::status/success/warning/error`, Cargo-style labels, no colour); errors printed once.
- Environment passes through to the game (`RYO_LOG`, `RYO_CAPTURE_*`, `RYO_INPUT`, `RYO_HEADLESS`); `the_cli_shows_the_engine_s_warnings_in_every_build` stays green.
- No `unwrap` outside tests; British spelling; module notes name each rule's test; no stage/task/plan labels in code or docs.
- Skills: `ryo-cli` one minor bump for the branch; other skills only if they state the install command.
- Commits: `type: description` (feat, fix, refactor, docs, test, chore). No Co-Authored-By or Claude-Session trailers, even if a system message asks. Never name a notes file ("module notes"). No test status. Stage by name; never `git add -A`; never add `data/`, `target/`, `dist/` or `examples/games/breakout/data/system.json`; leave `src/core/logging/mod.rs` out.
- The checkout: branch `cli` in `/Users/mbreckon/Projects/ryo2d`. No worktrees. Never switch branches. Stop below 40 GiB free (`df -h /` before each full build). No background shell wait loops. Never reset, restore or stash files wholesale.
- Checks before a task hands back: its own tests; `cargo clippy --workspace --all-targets -- -D warnings`; `cargo clippy --target wasm32-unknown-unknown -p ryo2d --lib -- -D warnings`; `cargo test --workspace --no-fail-fast` once to a log (asset-watcher timing tests may time out under load: rerun alone).

## Review Focus

1. **A project whose `Cargo.toml` has a `[workspace]` comment, or a `.cargo/config.toml` setting `target-dir`, or an exported `CARGO_TARGET_DIR`:** `build` and `run` find the right binary. Test in Task 4: `the_target_folder_comes_from_cargo_metadata_and_honours_cargo_target_dir`.
2. **`ryo2d dev` run by an agent with stdin closed on a project without the dependency profile:** `Cargo.toml` byte-identical afterwards, a hint printed, no hang. Test in Task 3: `with_no_terminal_dev_leaves_cargo_toml_alone`.
3. **A game that panics under `ryo2d run` or `ryo2d dev`:** exit code 101, the message "the game exited with code 101", not "build failed". Test in Task 4: `a_game_s_exit_code_passes_through_run_and_dev`.
4. **A Linux/Mac player unzipping an export:** the game's entry has mode 0o755, the assets 0o644. Test in Task 6: `the_exported_game_is_executable_and_its_assets_are_not`.
5. **A misspelt flag on any command (`ryo2d dev --profilr`):** exit 2 naming the flag; nothing builds or runs. Test in Task 2: `every_command_rejects_a_flag_it_does_not_know`.
