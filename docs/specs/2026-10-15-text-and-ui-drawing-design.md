# Text and UI Drawing (4a): Fonts, Rich Text, World Text, GPU-Drawn UI - Design

## Overview

Sub-project 4a of the professional-grade overhaul replaces everything under the UI's drawing and adds real text:

- a **text core**: fonts, Parley layout of styled spans with inline icons, markup, and per-glyph reveal and effects;
- a **glyph atlas** in the renderer: raster glyphs by swash, MSDF glyphs by `fdsm`;
- **world text**: a `Text2d` component drawn with the sprites;
- a **UI drawn on the GPU**: through the same 2D batch, at window resolution.

The immediate-mode `Scene::ui` call style stays.

Sub-project 4b (interaction) follows with its own spec. It covers:
- widget ids;
- hot, active and focus state;
- a layout engine;
- gamepad and keyboard navigation;
- the scene theme;
- retained UI nodes;
- the interaction bugs.

**Why:** the UI is still the CPU rasterizer the audit described (`docs/research/2026-10-11-engine-audit.md`, section 5). Verified at 52a6f3d:

- **The buffer:**
  - It is an RGBA `Vec<u8>` at logical resolution, cleared, scanned and fully uploaded every frame.
  - It is stretched to the window with nearest sampling, so text is blocky on HiDPI displays.
  - Translucent UI comes out too dark (premultiplied colour blended as straight alpha, `compositor.rs:216`), and glyphs force alpha 255.
- **Fonts:** the only font is an 8×8 ASCII bitmap (`ch as u8`, so non-ASCII draws blank or as the wrong glyph). The dev windows have a second 7×12 font. There is no TTF, shaping, size, outline or world-space text.
- **Scaling:** `ui_scale` is an integer that scales glyphs only, and anchored and centred text is measured unscaled.
- **Clipping:** `push_clip`/`pop_clip` are user-reachable `assert!`s.

**Owner decisions (2026-10-15):**
- **Split:** 4a is drawing and text; 4b is interaction.
- **Text needs (all four):**
  - crisp UI text at any DPI;
  - world text that stays sharp when the camera zooms or the text scales;
  - outlines and shadows;
  - pixel fonts for pixel art.
- **Formatting (all four):** styled spans, inline icons, typewriter reveal with per-glyph effects, and a markup string syntax.
- **Pixel-art mode:** the UI draws on the low-res target by default, so pixel fonts and panels share the art's pixels; a setting draws it at window resolution instead.
- **UI style:** both. 4a keeps the immediate call style and builds its drawing and text so 4b's retained nodes emit the same commands.
- **Approach A:**
  - Parley for layout (styled spans, inline boxes for icons);
  - swash for raster glyphs (hinted, crisp at exact sizes, exact pixel fonts);
  - a per-font MSDF option generated by `fdsm` (free scaling; outline, shadow and glow in the shader), as Godot 4 offers per font.
- **Breaking changes:** acceptable. Every `ui` hook in the examples is ported.

**Out of scope:**
- In 4b: widget ids, hot/active/focus state, a layout engine, gamepad/keyboard navigation, the scene theme, retained nodes, nested scroll views, hover and occlusion, slider drag occlusion, and tooltips.
- An asset-system rewrite (sub-project 5; fonts load through today's `AssetManager` path rules).
- Localization tables.
- Vertical text.
- Text on paths.
- Emoji beyond what the loaded fonts' colour glyphs give.
- Accessibility (screen readers).

## Architecture

| Path | Holds | Crates named |
|---|---|---|
| `src/core/text/` | `Fonts`, `FontId`, `FontRender`, `TextStyle`, `RichText`, `Span`, markup, `TextIcons`, `TextEffects`, layout and its cache, glyph rasterization (raster and MSDF) to bitmaps | `parley`, `swash`, `fdsm` (only here) |
| `src/core/text/world.rs` | `Text2d`, `TextBounds`, `TextReveal`, `TextRevealed`, the layout system | none |
| `src/core/render/batch/glyphs.rs` | the glyph atlas: pages, packing, eviction, uploads | `etagere` |
| `src/core/render/batch/` | `BatchShader::{TextMask, TextMsdf, UiRect}` and their WGSL | none |
| `src/core/render/ui.rs` | the UI draw list laid into the batch with a screen-space camera and scissors | none |
| `src/core/ui/` | `UiContext` records `UiCommand`s; widgets ported; `BitmapFont` and the CPU rasterizer removed | none |

**Data flow:**

```
Fonts + TextStyle + RichText/markup ─→ Parley layout (cached) ─→ positioned glyphs + icon boxes
        │                                                              │
        └─ glyph rasterizer (swash raster/stroke, fdsm MSDF) ─→ glyph atlas pages
                                                                       │
Text2d (world) ─→ DrawList items (z-sorted with sprites, per camera) ─┤
Scene::ui ─→ UiContext ─→ UiCommands (logical px) ─→ ui pass ────────┴→ Batch2D quads/triangles
```

The text core is GPU-free: it produces layouts (glyph ids, positions, styles, icon boxes) and glyph bitmaps. The renderer owns the atlas and the draws.

## Fonts

**Built-in fonts** (cargo feature `default-fonts`, on by default):
- **Inter** Regular and Bold (OFL-1.1), subset to Latin, Latin Extended, Greek and Cyrillic: the default UI and world font.
- **JetBrains Mono** Regular (OFL-1.1), subset: the console, debug overlays and dev windows.
- **m5x7** (CC0): the default pixel font.

The binary-size cost is measured in the plan (target about 0.5 MB). Without the feature, the first text draws tofu boxes and warns once until a game loads a font.

**Loading:**
- `ctx.assets.load_font(path) -> AssetResult<FontId>` (beside `load_sprite`) and `Fonts::add_bytes(bytes)` register a font. Variable and collection files are allowed.
- Families resolve by name.
- A `TextStyle` names a family or a `FontId`. Its fallback chain is the style's fallbacks, then the built-in font of its role.
- A missing glyph draws the font's `.notdef` (tofu) and is warned once per font and character.
- `Font::bitmap(sprite, cell, chars)` makes a pixel font from a grid sprite sheet. Its glyphs are regions of the sprite in the existing sprite atlas.
- On the web there are no system fonts: only the built-in and loaded fonts.

**`FontRender`, per font:**
- `Raster` (default): swash with hinting, subpixel horizontal positioning (four bins), rasterized at the exact physical size.
- `Pixel`: no anti-aliasing, no subpixel bins. Sizes snap to whole multiples of the font's design size, and glyphs land on whole pixels. Bitmap fonts are always `Pixel`.
- `Msdf { base, range }`: glyphs generated once by `fdsm` at a base size (default 32 px, distance range 4 px), then drawn at any size. Outline, soft shadow and glow come from the shader.

## Text style and layout

`TextStyle` (`#[non_exhaustive]`, with builders) holds:
- font (family or id) and fallbacks;
- size in logical pixels (world units for world text);
- weight and italic;
- colour;
- line height (a multiplier) and letter spacing;
- `outline: Option<Outline { width, color }>`;
- `shadow: Option<Shadow { offset, color, softness }>`;
- `glow: Option<Glow { radius, color }>`.

How each effect renders, by font mode:

| Effect | Raster | MSDF | Pixel |
|---|---|---|---|
| Outline | swash's stroke rendering: a second atlas entry drawn under the fill | in the shader | |
| Shadow | a hard offset copy | soft, in the shader | |
| Glow | not supported (warned once per style) | in the shader | |

If the spike finds swash's stroke rendering poor, raster outlines use a coverage dilation in the shader instead.

`TextLayoutOptions` holds:
- wrap width (`None` is a single line);
- `TextAlign { Start, Center, End, Justify }`;
- `max_lines` with `TextOverflow { Clip, Ellipsis }`;
- an `Anchor` for which point of the block sits on the position.

**The layout cache.** Parley shaping is the costly step. A layout is cached by text, style, options and the fonts' generation, so an immediate `ui.text(..)` call each frame reuses last frame's layout. Entries unused for 120 frames are dropped. A font load bumps the generation, so text waiting on it lays out again. Hits and misses are counted for tests and the benchmark.

## Rich text, icons, markup

**Spans.** `RichText::new("Deal ").span("20", Span::color(RED)).plain(" damage")`. A `Span` overrides parts of the base style: colour, size, font, weight, italic, outline and effect.

**Inline icons:**
- `.icon(sprite)` or `.icon_named(name)` is a Parley inline box. It is sized to the line height by default or set explicitly, sits on the baseline, and is drawn as a sprite quad in the same batch item.
- The `TextIcons` resource maps names to sprites or atlas regions, so a game swaps keyboard and gamepad icon sets in one place.
- An unknown name draws an empty box of that size and is warned once.

**Markup.** `RichText::markup(&str)`:
- Tags: `[color=#rrggbb|name]`, `[size=n]`, `[font=family]`, `[b]`, `[i]`, `[outline=width,color]`, `[icon=name]`, `[pause=seconds]`, and effect tags (`[wave]`, `[shake]`, `[rainbow]`, and any registered name).
- `[[` escapes a bracket.
- A malformed, unknown or unclosed tag renders as literal text and is warned once per markup string; it never panics.
- Parsed markup is cached with the layout.

**Reveal.**
- A text shows its first N grapheme clusters.
- World text takes a `TextReveal { per_second, punctuation_pause, fade }` component, which advances on game time, honours `[pause]`, and writes `TextRevealed { entity }` when the whole text shows.
- In the UI, `ui.text(..).reveal(n)` takes a count or fraction the caller advances.
- Revealed glyphs can fade in over a set time.

**Per-glyph effects:**
- Built in: `wave { amplitude, frequency }`, `shake { intensity }`, `rainbow { speed }`.
- `TextEffects::register(name, fn(GlyphContext) -> GlyphMod)` adds a custom effect. The function sees glyph index, cluster, time and line, and returns an offset, a scale and a colour.
- Effects run when glyph quads are built each frame, with no relayout.
- UI effects use real time. World-text effects use game time, so they freeze under pause and slow with slow motion, like sprites.

## The glyph atlas and the batch

**Keys.** A glyph key is: font, glyph id, physical pixel size, subpixel bin, and stroke width (outline entries).
- UI text uses its exact physical size (logical size × `ui_scale`).
- World text with a raster font uses the size the camera sees (size × zoom × entity scale × scale factor), snapped to size steps (1 px up to 32, 2 px up to 64, 4 px beyond) and drawn scaled by the remainder, so a zooming camera does not churn the atlas.
- MSDF glyphs have one key per glyph.

**Pages:**
- R8 coverage pages (raster), RGBA pages (colour glyphs) and linear RGBA pages (MSDF), 1024² each, up to 8 pages per kind.
- Packed with etagere's bucketed allocator.
- The least recently used glyphs are evicted, never those drawn this frame.
- A frame that needs more than every page holds warns once and draws what fits.
- New glyphs upload as small `write_texture` rectangles; nothing uploads a whole page per frame.
- Bind groups are made with their page, so the existing steady-frame guard (`steady_frames_create_no_bind_groups`) covers text.

**Draws.** Glyphs are instanced quads in the batch's quad stream with three new `BatchShader` entries:
- `TextMask` tints coverage and writes premultiplied colour.
- `TextMsdf` takes the median of the three distances and applies the outline, shadow and glow parameters carried in the instance's parameter lanes.
- `UiRect` draws an anti-aliased rounded rect with a border from a distance function.

Outline and shadow quads go just before their glyphs in the same item. Consecutive glyphs on one page merge into one draw (the batch's existing `DrawState` merging). Icons are sprite quads in the same item.

**Colour.**
- World text blends in linear light on the scene image, so it is tonemapped and post-processed like sprites.
- The UI draws after tonemapping and post-processing, untouched by them.
- Everything is premultiplied, which fixes the old darkening.

**Pixel fonts** sample nearest and use the batch's existing axis-aligned pixel snap (`CameraGlobals::snap`).

**MSDF generation** happens on a glyph's first use, synchronously. `Fonts::prewarm(font, chars)` builds glyphs ahead (in a loading scene), so that text never appears late. The spike and the benchmark measure the per-glyph cost.

## GPU-drawn UI

**`UiContext` records commands.** It keeps its immediate call style but records `UiCommand`s in logical UI pixels:
- rects (fill, optional corner radius and border);
- nine-slice panels from a sprite;
- sprites;
- lines and polylines (through the batch's polyline builder);
- text (a cached layout plus its effects and reveal).

Its parts:
- **Clipping** is a scissor stack with no depth limit; nested clips intersect. `pop_clip` on an empty stack is warned once, not asserted.
- **Order:** commands draw in submission order, the painter's algorithm. A popup layer (dropdown lists, tooltips later) is flushed last, replacing the caller's `finish_dropdowns` step.
- **Measuring** (`ui.measure_text`) uses the same layout as drawing, so measured and drawn text always agree.

**Scale and resolution:**
- `ui_scale: f32` maps logical UI pixels to physical pixels. The default is the window's scale factor; `EngineBuilder::ui_scale(Option<f32>)` and `ctx.request_ui_scale(Option<f32>)` (both `u32` today) set it, `None` meaning the scale factor.
- `ui.screen_size()` is in logical pixels.
- Text rasterizes at physical pixels, so it is sharp at 1× and 2×.
- `UiResolution { Window, Target }`:
  - In the default presentation the UI is always at window resolution.
  - In pixel-art mode the default is `Target`: the UI draws on the low-res display image before the composite, at scale 1 in target pixels, and is scaled with the art.
  - `Window` draws it at window resolution over the scaled art instead.

**The `ui` pass:**
- At window resolution, it draws onto the output after the composite places the scene image.
- At `Target` resolution, it draws onto the display image before the composite.

It uses the batch's pipelines (built per format on first use) with a screen-space camera uniform and per-command scissors. Captures include the UI, as now.

Removed:
- the UI texture;
- `Engine::ui_buffer` and its per-frame clear, scan and upload;
- `Compositor::upload_ui` and the straight-alpha blend;
- `BitmapFont`.

**Widgets.** Button, styled button, label, slider, checkbox, toggle, text input, dropdown and both scroll views keep their behaviour and, where they still make sense, their signatures. They draw with the new commands, and their text calls take a `TextStyle` (or size and colour shorthands). The text input takes caret positions, selection rectangles and click hit-testing from the Parley layout (grapheme clusters), so non-ASCII and IME text edits correctly. Its focus model stays as it is until 4b.

## World text

`Text2d` (`#[non_exhaustive]`, builders, `#[require(Transform, TextBounds)]`) holds:
- content: plain, `RichText` or markup;
- `style: TextStyle`;
- `layout: TextLayoutOptions` (wrap width in world units);
- `lit: bool` (default `false`);
- `z_order`;
- `filter`.

```rust
commands.spawn((
  Transform::from_xy(x, y),
  Text2d::markup("[b]Shop[/b]").with_style(TextStyle::new().size(16.0)),
));
```

**Layout** is computed into a crate-internal component when `Text2d` changes or a font loads (`PostUpdateSet::Extract`, before drawing). `TextBounds` exposes its size and anchor offset.

**Drawing.** World text joins the draw list at its `z_order` with its `RenderLayers` (a new `DrawKind::Text`, after entities at equal z):
- interpolated through `PreviousGlobalTransform` like other entities;
- rotated and scaled by its transform;
- culled per camera by its bounds.

Raster glyphs are keyed per camera at the size that camera sees.

**Lighting:** unlit by default, since labels and damage numbers stay readable in the dark; `lit: true` draws it in the lit stream like a sprite.

**Pixel-art mode:** pixel fonts snap to whole target pixels.

**Reveal and effects** use game time (`TextReveal`, `TextRevealed`).

**Damage numbers** are a recipe in the skill: `Text2d` plus the existing tweens (rise, fade) plus despawn on finish. No new system.

## Public API changes

- **New in the prelude:** `Fonts`, `FontId`, `FontRender`, `Font`, `TextStyle`, `Outline`, `Shadow`, `Glow`, `RichText`, `Span`, `TextIcons`, `TextEffects`, `GlyphContext`, `GlyphMod`, `TextLayoutOptions`, `TextAlign`, `TextOverflow`, `Text2d`, `TextBounds`, `TextReveal`, `TextRevealed`, `UiResolution`.
- **`UiContext`:**
  - The `draw_text*` family takes a `TextStyle` or shorthands.
  - `ui.text(..)` returns a builder (reveal, effects, anchor, wrap).
  - New: `draw_rounded_rect`, `draw_nine_slice`, `measure_text`.
  - `ui_scale()` is `f32`.
  - `push_clip` and `pop_clip` never panic.
  - `finish_dropdowns` is removed (the popup layer).
- **Removed:** `BitmapFont`, `create_debug_font` and the UI buffer; `ui_scale` arguments become `f32`.
- **Console and overlays:** the console takes a font size and colours from its settings instead of a cell size.

## Design decisions

- **Parley, not cosmic-text.**
  - Parley has inline boxes, so icons in text work without placeholder tricks.
  - Its span model fits rich text.
  - Bevy 0.20 moved to it.
  - The cost is pairing it with swash for rasterization ourselves; the spike proves that first.
- **Raster by default, MSDF per font.**
  - Raster with hinting is the sharpest at small UI sizes and is exact for pixel fonts.
  - MSDF is the right tool for zooming and scaled world text and for glow.
  - Making it a per-font choice keeps each font on one path (Godot does the same).
- **Glyphs through the world's batch, not a separate text renderer.**
  - One set of pipelines, blend modes, cameras and z-sorting.
  - World text interleaves with sprites correctly.
  - The UI reuses the batch's bind groups and merging.
- **Text core free of the GPU.** Layout and rasterization are testable without a device, and 4b's retained nodes reuse them.
- **The UI draws after tonemapping, onto the output.** UI colours are what the game specified, unaffected by exposure, grading or post effects (as today). In pixel-art mode it goes on the low-res image by default, so it shares the art's pixels.
- **Size steps for world text under zoom.** Exact sizes would rasterize a new glyph set every zoom frame; steps bound the atlas at a few percent of scaling.
- **Immediate calls cached by content.** An immediate API redraws every frame. The layout cache makes that cost a hash lookup, so the immediate style stays cheap without a retained tree.

## Risks

- **Parley and swash pairing:** Parley gives glyph ids and font data, and swash must rasterize them identically. The spike proves it before anything is built on it.
- **Raster outline quality:** if swash's stroke output is poor at small sizes, the fallback is a shader dilation of coverage. It is uglier at large widths; MSDF fonts are the answer there.
- **MSDF generation cost:** if `fdsm` is slow, first-use glyphs could hitch a frame; prewarm covers known text. The benchmark decides whether a per-frame budget is needed.
- **Binary and wasm size:** three subset fonts plus Parley and swash add to the web build. The cost is measured; the `default-fonts` feature lets a game ship its own fonts only.
- **Port volume:** 78 `ui` hooks and the demo-kit chrome. The port is mechanical for `draw_text`/`draw_rect` but large; the GPU path runs beside the CPU path until every example is ported, so each step stays green.
