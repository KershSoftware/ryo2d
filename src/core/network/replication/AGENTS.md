# Replication Module - AGENTS.md

## Purpose

The `replication/` module provides automatic synchronization of game state between server and clients. It implements a host-authoritative model where the server owns the truth and clients receive updates.

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                    ReplicationManager                           │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐  │
│  │ComponentRegistry│  │  DirtyTracker   │  │  Entity Maps    │  │
│  │ (serializers)   │  │ (delta sync)    │  │ (NetworkId↔Entity)│ │
│  └─────────────────┘  └─────────────────┘  └─────────────────┘  │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│                    Network Messages                             │
│  ┌──────────┐ ┌───────────┐ ┌───────────────┐ ┌──────────────┐  │
│  │SpawnEntity│ │DespawnEntity│ │ComponentUpdate│ │FullStateSync│  │
│  └──────────┘ └───────────┘ └───────────────┘ └──────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

## Key Types

### NetworkId

Unique identifier for networked entities (u64). Generated by the server and consistent across all clients.

```rust
let id = NetworkId::new();          // Generate new (server only)
let id = NetworkId::from_raw(42);   // From network message
```

### NetworkEntity

Component marking an entity for network replication:

```rust
pub struct NetworkEntity {
    pub network_id: NetworkId,  // Unique network identifier
    pub owner: ClientId,        // Who owns this entity
    pub authority: Authority,   // Who can modify it
}
```

### Authority

Controls who can modify an entity:

```rust
pub enum Authority {
    Server,              // Server controls (default)
    Client(ClientId),    // Specific client controls (player entities)
}
```

### Replicated Trait

Components implement this for automatic network sync:

```rust
pub trait Replicated: Component + Serialize + DeserializeOwned + Clone {
    fn component_id() -> ComponentTypeId;
    fn component_name() -> &'static str;
    fn replication_priority() -> u8 { 1 }  // Higher = more frequent
}
```

Built-in implementations:
- `Transform` (priority 10) - position, rotation, scale
- `Velocity` (priority 5) - movement speed

### ComponentRegistry

Type-erased serialization registry:

```rust
let mut registry = ComponentRegistry::new();
registry.register::<Transform>();
registry.register::<Health>();

// Serialize
let serialized = SerializedComponent::from_component(&transform)?;

// Deserialize and apply to entity
registry.deserialize_and_apply(&serialized, &mut world, entity)?;
```

### NetworkedValue<T>

Wrapper preventing silent mutations of replicated values:

```rust
use ryo2d::prelude::*;

// Create a component with networked values
#[derive(Component, Clone, Serialize, Deserialize)]
struct Position {
    x: NetworkedValue<f32>,
    y: NetworkedValue<f32>,
}

// Reading doesn't mark dirty (uses Deref)
let x = *pos.x;  // or pos.x.get()

// Writing requires explicit methods (marks dirty)
pos.x.set(new_x);
pos.y.modify(|y| *y += 10.0);

// Check if any values changed
if pos.x.is_dirty() || pos.y.is_dirty() {
    replication.mark_dirty::<Position>(entity);
}

// Server correction (doesn't mark dirty)
pos.x.apply_server_correction(server_x);

// Optional: only set if changed
pos.x.set_if_changed(new_x);  // Returns true if changed
```

Key features:
- Implements `Deref` for read access, NOT `DerefMut`
- `set()` and `modify()` mark the value as dirty
- `apply_server_correction()` sets value without marking dirty
- `set_if_changed()` only marks dirty if value actually changed
- Dirty flag is NOT serialized (fresh on deserialize)

### DirtyTracker

Generation-based tracking for delta updates:

```rust
let mut tracker = DirtyTracker::new();

// Mark component changed
tracker.mark_dirty(network_id, ComponentTypeId::from_name("Transform"));

// Get dirty components for a specific client
let dirty = tracker.get_dirty_for_client(client_id);

// Acknowledge client received updates
tracker.acknowledge_client(client_id);

// Advance to next generation
tracker.next_generation();
```

Key behavior:
- Unregistered clients see ALL dirty components (for initial sync)
- Registered clients only see changes since their last acknowledgment
- Spawned/despawned entities tracked separately

### ReplicationManager

Central hub for all replication operations:

```rust
// Server
let mut replication = ReplicationManager::new_server();
replication.register::<Transform>();

// Spawn networked entity
let entity = replication.spawn_networked(&mut world,
    NetworkEntityBuilder::new()
        .server_owned()
        .with_component(Transform::new(0.0, 0.0))
);

// Mark dirty after modification
replication.mark_dirty::<Transform>(entity);

// Broadcast to clients
replication.broadcast_updates(&mut world, &mut server);

// Send full state to new client
replication.send_full_state(&world, &mut server, new_client_id);
```

```rust
// Client
let mut replication = ReplicationManager::new_client();
replication.register::<Transform>();

// Process incoming messages
replication.process_incoming(&mut world, &mut client);

// Look up local entity from network ID
if let Some(entity) = replication.get_entity(network_id) {
    // Use entity
}
```

### NetworkEntityBuilder

Fluent API for creating networked entities:

```rust
let builder = NetworkEntityBuilder::new()
    .server_owned()                              // or .client_owned(client_id)
    .with_component(Transform::new(100.0, 200.0))
    .with_component(Velocity::new(5.0, 0.0));

let entity = replication.spawn_networked(&mut world, builder);
```

## Message Types

| Message | Channel | Purpose |
|---------|---------|---------|
| `SpawnEntityMessage` | ReliableOrdered | Create entity on clients |
| `DespawnEntityMessage` | ReliableOrdered | Remove entity from clients |
| `ComponentUpdateMessage` | Unreliable | Single component delta |
| `ComponentBatchMessage` | Unreliable | Multiple component deltas |
| `FullStateSyncMessage` | ReliableOrdered | Initial state for new clients |

## Design Decisions

### No Proc-Macros (v1)

The `Replicated` trait requires explicit implementation rather than derive macros. This keeps the implementation simple and avoids proc-macro complexity.

### JSON Serialization

Components are serialized as JSON for simplicity and debugging. Binary serialization (e.g., bincode) could be added for performance.

### Generation-Based Dirty Tracking

Each component modification is tagged with a generation number. Clients track their last acknowledged generation, so they only receive changes they haven't seen.

### ListenServer Optimization

The `ServerLike` trait's `is_host()` method allows skipping network serialization for the host player in a listen server.

## Usage Patterns

### Spawning Player Entities

```rust
// When client connects
fn on_client_connected(&mut self, client_id: ClientId) {
    let entity = self.replication.spawn_networked(&mut self.world,
        NetworkEntityBuilder::new()
            .client_owned(client_id)  // Client has authority
            .with_component(Transform::new(spawn_x, spawn_y))
            .with_component(PlayerController { client_id })
    );

    self.players.insert(client_id, entity);
}
```

### Handling Component Changes

```rust
// After modifying a replicated component
if let Some(mut transform) = world.get_component_mut::<Transform>(entity) {
    transform.x += velocity.dx * dt;
    transform.y += velocity.dy * dt;
}
replication.mark_dirty::<Transform>(entity);
```

### Full State Sync for New Clients

```rust
// When client connects
replication.register_client(client_id);
replication.send_full_state(&world, &mut server, client_id);
```

## Notes for AI Agents

1. **Register identical components** - Server and client must register the same types
2. **Mark dirty after changes** - Call `mark_dirty::<T>()` after modifying replicated components
3. **Use appropriate channels** - Spawns use ReliableOrdered, updates use Unreliable
4. **Handle entity lookup failures** - `get_entity()` returns `Option`, entity may not exist yet
5. **Authority matters** - Only the authority (server or specific client) should modify components
6. **Call broadcast_updates() each frame** - Even if nothing changed, it advances generations
7. **Don't serialize non-replicated components** - Only components implementing `Replicated` are synced
