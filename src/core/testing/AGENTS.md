# AGENTS.md - Headless Testing

`ryo2d::testing` has two harnesses: `HeadlessEngine`, the whole engine on an offscreen GPU, and `UiHarness`, UI frames with no GPU at all (see UiHarness below). The module is native only. `asset_world()` is a world with the asset registry and nothing else (`insert_registry` over an empty `MemorySource`), for a test outside the crate that needs handles, since a store comes only from a world (asset module notes); `asset_world_over(files)` (doc-hidden) is the same over a `MemorySource` the caller keeps, for a bench that loads files without an engine (`benches/tilemap.rs`). `audio_world()` adds a `Time` and an `AudioEngine` on the mock backend with its log on and its picks seeded (`HEADLESS_SEED`, as a headless engine's), `audio_world_over(files)` is the same over a `MemorySource` the test keeps (to save over a file and `AssetServer::reload` it), and `audio_step(world, dt)` is one frame of it (advance the clock, pump, `audio_system`, then clear the change trackers as the engine's `Last` does, so the removal message each `audio_system` writes as it takes its engine out of the world does not grow a buffer). The mock renders inside `audio_system`, on the calling thread, where a device renders on its own; `AudioEngine::mock_render_time()` (doc-hidden) is how long the last frame's rendering took, which `benches/audio.rs` leaves out of the main thread's time.

`HeadlessEngine` (`ryo2d::testing`) runs the real engine without a window: an offscreen `WgpuRenderer`, one `Engine::frame` per `step`, pixels via `frame()`. Spec: `docs/specs/2026-10-10-headless-rendering-design.md`.

## How it fits

- `HeadlessEngine::new(builder)` → `EngineBuilder::build_headless` → `Engine::new(.., headless: true)` → `init_gpu(WgpuRenderer::new_offscreen(..))` on the `shared_gpu()` device, which inserts the `Gpu` resource and enters the start scene. `new_or_skip` returns `None` (printing a skip line) when there is no GPU.
- `step()` calls the same `Engine::frame` as the window loop with one fixed timestep as the frame's real time: the full frame runs (`First`, the UI pass, the fixed steps, `Update`, `PostUpdate`, render, `Last`), and at game speed 1 that is exactly one fixed step. A paused or hitstopped game clock runs none and slow motion runs fewer, as in a windowed run. `step_real(real)` (doc-hidden) is the same frame with a real delta of the test's choosing (at a 60 Hz step, two fixed steps at 1/30 s, sometimes none at 1/144 s), panicking if the frame fails, for tests of frame-rate independence and of what runs on real time.
- Input is queued on `Input` (`InputEvent`) the way window events are and published when the next frame begins. `tap_key` queues the release after the step that saw the press. The UI pass runs before the fixed step, so a scene that records input in `update()` and draws it in `ui()` shows the previous step's value; probe with `ui.input()` in `ui()` when the frame must show the current one.
- `world()` / `world_mut()` reach the ECS between steps; `frame()` reads the last presented frame (scene + UI) at game resolution.
- **Two runs compared.** Scene scope ids count per engine (`SceneManager`), so two engines built and driven the same way in one process give their UI the same ids. `ui_snapshot()` (doc-hidden) is the last frame's UI in `Debug` form, as `UiHarness::frame_snapshot` (the same `ui_snapshot` function): the commands that can show (with their slots) and the slot table, records, focus, node events, the interaction, widget states with their values, modals, the actions navigation used, rebinds, consumed input and every node's components; `ui_cache_stats()` (doc-hidden) is what the node walk built, replayed and did with fragments. `examples/demos/ui/tests/cache.rs` and breakout's `tests/cache.rs` compare an engine with `EngineBuilder::ui_cache(false)` against one with caching on, frame by frame.
- **Two engines' pixels compared.** `PixelPair` (`retain.rs`, doc-hidden) builds two engines from one `EngineBuilder` maker, steps them together and panics on a frame whose pixels differ (saving both as PNGs), in the frame and, where the window is not the game's resolution, in the window too: `PixelPair::new` with UI render retention on and off, `PixelPair::fragments` with fragments on against the node cache off (a full rebuild every frame), retention on in both and the engine's debug spot check as it defaults. It counts what the first engine kept, reused, copied, resolved again and copied into the shader's slots, for a test to assert the run did what it set out to. The ui demo's and breakout's `tests/fragments.rs` and `tests/retain.rs` drive it.
- **Doc-hidden reads for the engine's tests**: `ui_runs_snapshot()` (the last frame's fragment runs, which `ui_snapshot` leaves out, since with fragments off there are none), `ui_scroll_slots()` (each scroll slot's clip and drawn origin, to assert a scroll moved), `ui_scrollbars()` (each scrollbar drawn whose thumb shows: its area, axis, track and thumb, which `ScrollState` keeps as drawn, to press and drag the thumb), `ui_render_stats()` (`UiRenderStats`: whether the image was kept, texts and fragment runs built and copied, instances written), `ui_draw_count()`, `debug_stats()` (the last frame's `DebugStats`, unsmoothed: sprites submitted, the engine's particles among them, live particles and the budget), `render_time()` and `ui_pass_time()` (the render step's and the UI pass's CPU time, which `benches/ui_render.rs` guards), `particle_systems_time()` and `idle_particle_systems(calls)` (the particle systems' CPU time in the last frame, and `calls` runs of them outside a frame; `benches/particles.rs`), `tile_chunks()` (the tile chunks the batch holds built, each a layer entity and its signed chunk, for tests of what a view built and culled), `tile_draws()` (the last frame's tile chunk draws in draw order, each a layer, chunk, tileset and the run of the tileset's instances it draws, for tests of how a layer's chunks draw), and `set_ui_spot_check(bool)` (the node cache's debug spot check, on in debug builds).
- **UI focus.** `ui_focused()` is the focus the last step resolved; `ui_focusables()` is `nav::nav_targets` over the frame just drawn (what the D-pad can land on in the top scene: focusable, enabled, shown, in a scope, not `nav_skip`, inside the innermost open modal or trap, with rects in UI units); `focus_ui(id)` is a `request_focus` the next step's resolve applies. Between frames `UiMemory::drawn` reads this frame's records (the resolves, inside a frame, read last frame's), so the list matches what `frame()` shows; the trap is the one the last resolve kept on `modal_stack`, so read it a frame or two after a modal opens or closes. The ui demo's `tests/acceptance.rs` walks its four acceptance pages (Settings on each tab and with a list open, Dialogue before and after Skip) and the Menus dialogs this way.

## Logs in tests

`capture_log()` and `capture_log_bounded(limit)` (the logging module's, re-exported here with `LogCapture`) are how a test reads the log; the rules are the logging module notes' (Capture). Open the capture before the `HeadlessEngine`, `asset_world()` or `audio_world()`: the threads they start take the scope they are started in, so one started first logs outside the capture. The headless engine logs to stderr in every build and opens no log file, and a failing test prints its captured records in its own output. Doc-hidden, in a build with the tools: `console_run(line)` (the lines a typed line printed), `console_lines`, `console_open` and `console_fill` (the console's output, for `tests/e2e/dev_tools.rs` and `benches/dev_tools.rs`), `log_feed()` (a logger window's reading with no window), `tools_time()` (the last frame's console tick), and the free functions `log_ring_len()`, `set_log_stderr(on)`, `open_log_file(folder)` and `close_log_file()` (the bench's file). `resolved_debug(ryo_toml, profiler)` (doc-hidden, every build) is the engine's debug switches as a project resolves them, for `tests/no_tools.rs`. `tests/no_tools.rs` is `#![cfg(not(dev_tools))]`, so a debug check, clippy or test sees an empty file: `./dev check` (`dev.sh` and `dev.ps1`) also runs `cargo check -p ryo2d --release --test no_tools`, and `./dev test:all` also runs `cargo test -p ryo2d --release --test no_tools`.

A demo's or game's test counts its entities with a query for its own marker component, not `world.entities().len()`, which counts reserved slots too.

## UiHarness

`UiHarness` (`ui.rs`) is the engine's UI frame with no window, GPU or engine: a `UiMemory`, a `LayoutEngine`, a `TextEngine` synced to the built-in fonts, the `UiCommands` and a world of its own for UI nodes and the asset registry, at a UI size of the caller's choosing, scale 1, the dark theme (`with_theme` for another). Games unit-test UI functions with it, and `benches/ui.rs` measures UI frames with it.

- **One `frame` is one engine UI pass**, 1/60 s after the last: `begin_frame` on the memory and the layout, `resolve_pointer`, `apply_scroll_requests`, `route_wheel`, `resolve_focus` (with the theme's timings), `drag_ahead` and `update_lists`, then the node trees and the closure as the top scene (scene 1) between `begin_scene` and `end_scene`, then `end_pass` on the commands and `end_frame` on the memory, the layout and the text cache. The closure's value is returned.
- **Scripted input lasts one frame**: `move_to` (the pointer stays), `press` (held until `release`), `release`, `wheel(dx, dy)` in lines, `trackpad(dx, dy)` in logical pixels (a UI unit here), and `action(name)` for the nine `ui.*` actions, set straight on the frame's `NavInput` (no `Input`, no bindings). Another name warns once (`warn_once`, keyed by the name) and does nothing.
- **Reads**: `focused()` is `Interaction::focused` after the frame (it is always the top scene); `command_count()` the commands the last frame recorded.
- **Assets**: `assets()` is the harness's asset registry, as scenes reach it with `ctx.assets()`: an `AssetServer` over an empty `MemorySource`, or the source `with_asset_source` gave (a `DiskSource` over a folder, or the test's own `MemorySource`). Each `frame` runs the pump first, as the engine does.
- **A frame that records nothing** rewinds the memory (`UiMemory::rewind_frame`) and skips the node cache's `end_frame`, so a read (`ui.scroll_offset(id)`) between frames leaves the UI, and every node record, as the last drawn frame left them; the crate's `UiDriver` relies on it.
- **The node cache**: `set_ui_cache`, `set_ui_fragments` and `set_ui_spot_check` are harness fields copied into the cache before each walk (so they work before `spawn_ui`); the spot check is off by default, unlike the engine's debug builds, so counts stay exact. `ui_cache_stats` is the last walk's `UiCacheStats`; `set_theme`, `resize` and `type_text` change the environment and the input for the next frame. Doc-hidden, for the engine's tests: `frame_snapshot` (shared with `HeadlessEngine::ui_snapshot`), `check_change_ticks` and `age_change_ticks` (the kept tick's clamp), `ui_dirty_check` (the bench of the dirty check alone).
- **`UiDriver`** (`src/core/ui/test_util.rs`, tests only) holds a `UiHarness` and derefs to it (`d.memory`, `d.commands`), adding the crate-only script (keys, IME, Shift, pad buttons, held directions, the stick, the device, the scene, prompts) and reads (sounds, the navigation outcome, captured rebinds). `UiHarness` keeps those fields `pub(crate)` for it.

## Gotchas

- One process-wide device (`shared_gpu`): concurrent device creation deadlocks on Windows. `tests/common/gpu.rs` reuses it.
- Headless mode plays sound on kira's mock backend, silently: `ctx.audio()` works as on a device, rendered by the frame's real time (one fixed timestep per step), and `audio_log()` (doc-hidden) is the engine's audio log, on from before the start scene enters. Its audio picks and draws start from a fixed seed (`Engine::new` seeds them when headless, `RYO_HEADLESS` too), so a sound's variations repeat run to run; `audio_world()` starts from the same seed (`AudioView::seed` overrides either). Saves stay in memory, in a `MemorySaves` store (the builder's `memory_saves`, else a new one) that `saves()` returns, so a test can plant a save or read what the game wrote; dropping the engine finishes the queued writes. `save_to_folder(dir)` (doc-hidden) moves the saves and the settings file to a folder on disk from then on (`benches/saves.rs`, for a write's disk cost); `saves()` still gives the memory store. No real gamepads (`press_pad`, `tap_pad`, `set_stick` drive a virtual pad), hot reload, dev windows or user preferences, ignores `RYO_CAPTURE_*` and `RYO_INPUT`, and forces the FPS, timing and stats overlays off. Engine debug keys (F1-F5, F9, F10, F12) are inert, so injected F-keys reach the game like any other key; the console key (`` ` ``) still toggles the console when `[debug] console` is on (the default in a build with the tools). Keep new wall-clock-dependent features out of headless frames the same way.
- Particles repeat headless: a headless engine seeds its particle store with `PARTICLE_HEADLESS_SEED`, and each emitter draws its own seed from it in the order emitters are added, so the same scene gives the same particles run to run; `ParticleEmitter::with_seed` fixes one emitter's stream whatever else the scene adds. `particle_positions(world, emitter)` (doc-hidden) reads where an emitter's particles are.
- Tests in this module reach engine internals (`HeadlessEngine::engine`, `Engine::sprite_gpu`); pixel-level checks belong in `tests/e2e/`.
