# AGENTS.md - Asset Module

- **The registry.** `AssetServer` (a resource, cheap to clone) loads assets by asset path through `AssetLoader`s chosen by extension: on worker threads with `load` / `load_with`, which return a `Handle<T>` at once, or on the calling thread with `load_now`. Each type's values are in its `Assets<T>` resource (`register_asset`; `insert_registry` registers the engine's types and loaders). A handle keeps its asset alive; the pump frees it once the last handle drops. Scenes reach all of it through `ctx.assets()` (`AssetsView`), systems as `Res<AssetServer>` and `Res<Assets<T>>` / `ResMut<Assets<T>>`.
- **Paths** are relative to the asset root (`Workspace::assets_dir()`; an example's root is its own `assets/`), normalised lexically (`path.rs`). Asking for a path again while its asset lives gives the same handle, loaded, loading or failed. `state`, `is_ready` (dependencies too), `progress(ids)` and `stats()` say how far loading has got.
- **The pump** (`pump.rs`, run by `asset_registry_system` in `PreUpdate`, every frame) reloads changed files, inserts finished loads once their dependencies are loaded and their loader's `check` passes, frees unheld assets and sends each type's `AssetEvent`s (`Added`, `Modified`, `Removed`, `Failed`, `ReloadFailed`), for loads, reloads and changes made in code alike; `load_now` sends its `Added` or `Failed` at once. The font registry follows the font stores right after it (`fonts_follow_assets`).
- Hot reload is the registry's: with `EngineBuilder::hot_reload` on, its `DiskSource` watches the asset folder, and a saved file reloads under the same handle once its writes settle; a reload that fails keeps the last good value (`ReloadFailed`).
- Audio is not a registry asset: it has its own manager (`audio/`).
- `AssetServer` must stay `Send + Sync`: it is a resource, and its state is shared with the worker threads and the watcher (crossbeam channels; a poisoned lock is recovered with `PoisonError::into_inner`).
- **UI files** (`.ui.ron`) are registry assets: `UiFileLoader` (`loaders/ui_file.rs`) loads a file's imports and the images it names as its dependencies, and its `check` builds the root and every template against them; a reload rechecks the files that import it. A dependency that fails on the workers reaches the pump as the server's `Dependency` error, which a loader's `dependency_failed` may replace with a better one (the UI file loader names the position); the default keeps it. The UI module notes (Files) say how trees follow a file.
- **Themes** (`.theme.ron`) are registry assets: `ThemeLoader` (`loaders/theme.rs`) merges a file over the dark theme and loads its skins' images as its dependencies, so an image that does not load fails the theme (`AssetError::Dependency`, under `load_now` and on the workers alike) and one that reloads makes the theme `Modified`. `UiTheme::follow` uses the asset again whenever its version moves; the UI module notes (Theme) say how.
