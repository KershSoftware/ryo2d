# AGENTS.md - Tilemap Module

Sub-project 6a replaces the old tilemap module. Design: `docs/specs/2026-10-29-tilemap-design.md`. What exists so far is the data model, the Tiled (JSON and XML) and LDtk loaders, maps spawned as entities and edited at runtime, and their layers drawn through the world batch: tile layers from cached chunks (y-sorted ones row by row among the entities), image layers and tile objects as sprites (render module notes, Tile chunks, and Image layers and tile objects); collision and the rest arrive task by task.

## What exists

- `tile.rs`: `Tile` (tileset index, id, `TileFlip`) and `TileFlip` (H, V, D bits as Tiled stores them; `rotated_cw` uses Tiled's table).
- `property.rs`: `PropertyValue` and `Properties` (insertion-ordered, typed getters; `int` accepts a whole float, `float` accepts an int).
- `tileset.rs`: `Tileset` (an `Asset`; atlas or collection; per-tile `TileData` with shapes, animation, probability; `WangSet`s) and `URect`, the engine's own texel rectangle (glam has none).
- `grid.rs`: `TileGrid`, a dense layer of 4-byte cells (0 empty; flips in bits 28..=31, tileset in 20..=27, id + 1 in 0..=19) cut into `CHUNK_SIZE` (32) chunks. Edits mark chunks dirty; `drain_dirty` hands each changed chunk out once in row order. A new grid has no dirty chunk. A tile that does not fit a cell (tileset over 255, id over 1,048,574) is refused by `set`.
- `map.rs`: `TileMap` (an `Asset`) of `MapLayer`s (`LayerInfo` plus a `LayerKind` of tiles, objects or an image) over `TilesetSource`s (asset handle or embedded `Arc`). `IntGrid::get` returns `None` for 0 as well as outside.
- `spawn.rs`: maps as entities. `MapRoot` (a `TileMap` handle, or an LDtk project and a level by identifier or iid; class tiles, IntGrid collision overrides, collision off, base z) on an entity whose `Transform` places the map's top-left corner. `spawn_maps` (`PreUpdate`, chained after the asset pump) spawns the layers, objects and class tiles, and sends `MapEvent::Spawned`, or `MapEvent::Failed` once per failure. `map_asset` resolves a root to its `TileMap`.
- `edit.rs`: `LayerRef` (name or index), finding a layer entity, cell reads and edits, world/cell conversions. `view.rs`: `MapsView` (`ctx.maps()`), the public face of `edit.rs`.
- `padded.rs`: each tileset's tiles copied into power-of-two cells of a padded `Image` of its own (edges extruded, so no filter or mip level reads a neighbour). The cells sit `margin` texels in from every side (`cell - 8` for cells over 8 texels): with the 8 texel border a texture puts around an image (`atlas::BORDER`), every cell starts on a multiple of its side and the texture's sides are whole cells. A padded image over 256 px gets a texture of its own with every mip level, and the GPU sizes each level by rounding down and spreads it over the whole texture: without the margins its levels from the fifth (16 texels a texel) mixed neighbouring cells into a tile, and those of a texture whose side was not a multiple of the level's texel drifted off the full-size one (`no_seams_at_any_zoom_or_subpixel_camera`, zoom 0.1). Known limit: a level samples only its tile while `2^level <= cell - tile side`, so tiles a little under a power of two (14, 15, 30 px: two texels of extrusion) can take in a neighbour once drawn below half size, and anything drawn below one texel a cell mixes cells. `PaddedLayout` says where each tile and animation frame sits; `PaddedTilesets` makes one per tileset, again when the tileset or an image of it changes (in place, keeping the handle), and frees those a round of `get`s did not ask for. An animated tile's frames take consecutive cells after the static ones; unequal frame times repeat frames to a common beat (past 128 cells, the mean time). `render/tiles.rs` turns a chunk into instances in layer-local pixels (lane layout in its module docs), and its `TileDrawer` draws spawned maps' tile layers: a map's tilesets padded each frame it exists (a disabled map's too, so its images stay; a disabled map draws nothing, `Disabled` not reaching its layers), hidden layers skipped, each visible chunk built once into the batch's chunk store and drawn at the layer's interpolated transform. A layer entity's own `RenderLayers` replace the map's for what it draws. Each padding gets a `serial` never given before, which the chunks' look stamp includes, so a tileset padded again rebuilds the chunks drawn from it. `TileGrid::chunk_version` and `version` stamp every change from one process-wide counter (R8 as amended), so a version never repeats, across grids and clones too: a layer whose `TileLayerData::grid` is swapped for another, even one filled the same way, redraws. A fill or `mark_all_dirty` is one change, one version; consumers keep their last-seen versions.

## Gotchas

- `tiled/`: Tiled's formats as registry assets. `raw.rs` holds what a file says (serde structs named as Tiled's JSON names them; `xml.rs` fills the same ones from TMX, TSX and TX, so every non-zero default is an `Option` and `build.rs` owns the defaults), `data.rs` decodes gids and layer data (CSV, base64, gzip, zlib, zstd via `ruzstd`, all bounded by the layer's cell count), `build.rs` turns raw into `TileMap` and `Tileset` and holds the checks, `json.rs` the `TiledMapLoader` (`.tmj`, `.tmx`) and `TiledTilesetLoader` (`.tsj`, `.tsx`), picking the reader by extension, `objects.rs` the objects of object layers and templates, `wang.rs` Wang sets, `project.rs` the Tiled project file and the property resolution (`Props::read`, `resolve_properties`).
- A path written in a file joins that file's folder; the registry normalises it and refuses one leaving the asset root. An inline tileset's paths resolve against the map's folder.
- External tilesets are dependencies and are not loaded while the map loads, so a gid is matched to a tileset by `firstgid` alone. The ids each tile layer uses are noted in `TileMap::used_ids` and measured against the tilesets in the map's `check`; the atlas image against the declared tiles in the tileset's `check`.
- Group layers flatten: offset adds, opacity and tint multiply, parallax multiplies, visibility ands, a non-normal blend passes down. Layer ids stay as written; a layer without one gets the next free id.
- Limits, each a load error naming the place: 1<<26 cells a layer or map, 256 tilesets a map, 1,048,575 tiles a tileset. Unsupported until 6b: isometric, staggered, hexagonal and oblique maps and infinite maps; layer blend modes other than normal, add, multiply and screen.
- A tileset's `tileoffset` is kept as `Tileset::tile_offset`.
- Objects: `MapObjectData::position` is always the top-left corner of the object's rectangle in map pixels and `rotation` (radians, clockwise on screen) turns it about that corner. Tiled rotates about the object's own position, which for a tile object is the tileset's `objectalignment` point (bottom-left by default), so a tile object's position is moved to where its top-left corner ends up. A map cannot look inside an external tileset while it loads, so a map with tile objects `cx.read`s the `.tsj` or `.tsx` for its `objectalignment` (`objects.rs::read_alignment`). Ids are Tiled's, as strings; object-reference properties are `PropertyValue::Object(id)`. Fields of `RawObject` an instance of a template can override are `Option`s: the instance starts as the template's object, its own fields win and properties merge by name. A template tile's gid is relative to the template's tileset, matched to the map's by resolved path (a tileset the map lacks is a load error). Templates load from `.tj` and `.tx`. The XML reader (`roxmltree`) leaves an absent attribute `None` and never defaults it, writes class members and numbers as the JSON would hold them, and bounds group nesting by `build.rs`'s `MAX_DEPTH`; its errors read `line L, column C: what`. An XML fixture's properties must be in Tiled's JSON order (alphabetical) for the twin test, which compares every `xml/` fixture with its JSON export field by field.
- The Tiled project (`project.rs`): `[tilemap] tiled_project` in Ryo.toml, `EngineBuilder::tiled_project` over it, else `project.tiled-project` at the asset root if there is one (a configured file that is missing is a load error). The loaders are registered with the path (`with_project`) after `insert_registry`'s default ones. It is read with `cx.read`, so saving it loads the maps again. `Props::read(place, raw, class)` resolves a thing's properties: written values lie over the class member's default, members it omits take the default, nested classes layer (instance over the member's default over the nested class's own), enums read by name (flags as a `List`). Without the project or the class, what is written is kept and `engine_warn!` names the class once per file.
- Wang sets load as written (`wangid` is clockwise from the top, 0 for no color); colors and tile ids are checked.
- `LayerInfo::occludes: None` means "as `collides`"; `lit` defaults to true.
- Spawned maps: the map entity gets a child per layer (`MapLayerRef`, the layer's `LayerInfo` as a component, a `Transform` at the layer's offset; `TileLayerData` for a tile layer, `ImageLayer` for an image layer), plus `MapIds` (objects by id) and the crate's `MapLayers` (layer entities by index). `TileLayerData` is the entity's own copy of the grid and IntGrid, with every chunk marked dirty at spawn (a new `TileGrid` has none) so the chunk renderer builds each once. Objects are children of their object layer: `MapObject` with a `Transform` at the centre of the object's rectangle (its point; a polygon's or polyline's origin, Tiled giving those no size), turned by its rotation, polygon points relative to it; a tile object keeps its `tile`, and a hidden object spawns with `visible: false` (games use hidden markers; drawing skips it). Tiles of a class the root registers are taken out of the copied grid and spawn as `MapTile` children of their layer at the cell's centre in the layer's cell size, listed by cell in the layer's `LayerTiles` (crate). The objects' entities are spawned and `MapIds` inserted before the `MapObject`s go on, so an `Add<MapObject>` observer can resolve references.
- Game observers run as each part arrives and may despawn the map, a layer or an object before its turn: the spawn checks each is alive (`get_entity_mut`, never `entity_mut`), skips what is gone, and stops (no `Spawned`) once the map is gone. Every child is spawned as `(Transform, ChildOf(parent))` first and its observed components inserted after (`child_of`): bevy runs `Add` observers before `ChildOf`'s insert hook, so an observer that despawned the parent of a child spawned whole would orphan it and fail the hook's queued `Children` update on the gone parent.
- Runtime edits place class tiles too: `set_tile`/`fill` with a tile whose class the root registers spawn a `MapTile` (the grid cell cleared) instead of writing the grid; a class tile on a cell any edit touches is despawned first (the same tile again changes nothing). A plain `fill` takes the class tiles in its region through `LayerTiles` and fills the grid in one go; a class-tile `fill` goes cell by cell. `tile()` reads the grid, so a cell holding a class tile reads `None`. `MapObject::reference` reads `PropertyValue::Object(id)`, treats Tiled's unset `"0"` (and an empty id) as none, and checks the entity is alive (no bookkeeping system: a despawned object just stops resolving).
- A map waits while its asset (or, for a map built in code, a tileset asset it names) loads; one despawned meanwhile (a scene's `SceneCleanup::WORLD`) or no longer a `MapRoot` is not in the query and spawns nothing; a disabled one waits until enabled. A failure is reported once per `Arc<AssetError>` (the registry shares one per failure), and a missing LDtk level once per project version; a failed map whose file is saved fixed spawns. `MapRoot`'s `on_discard` hook takes down a spawned map's layers (and `MapIds`, `MapLayers`, the reported failure) when the root is replaced or removed, so a new root spawns afresh.
- `MapsView` finds layers through `MapLayers` (by index, or the first by name), returns `None`/`false`/0 for a map not spawned, a missing layer, a non-tile layer or a cell outside, and marks `TileLayerData` changed only when an edit changed a cell. World/cell conversions take a layer (R7: cell size is per layer) and walk the `Transform`s of the layer and its ancestors as they are now, not `GlobalTransform`, so a map moved this frame converts before propagation; `world_to_cell` gives cells outside the layer too, and `None` for a layer scaled to nothing.
- `ldtk/`: LDtk 1.5.x projects (`.ldtk`) as `LdtkProject` assets, one `LdtkLevel` per level with its `TileMap`. `raw.rs` holds what a file says (LDtk's JSON names), `build.rs` the conversion and the checks (reusing `tiled::build`'s `fail`, `join`, `load_dep`, `check_tileset`, `check_used_ids`), `mod.rs` the types and `LdtkLoader`. A newer `jsonVersion` than 1.5 is a load error naming both versions; older loads. Tilesets are shared: `LdtkProject::tilesets` in definition order, each level's map embeds them all (a tile's `tileset` is the definition's index). A tileset with no `relPath` (LDtk's built-in icons) is a `Collection` with nothing to draw. `.ldtkl` levels are read with `cx.read` (saving one loads the project again); paths join the project's folder.
- LDtk levels: `layerInstances` list the top layer first, so layers are reversed (layer 0 draws first). `LayerKind::Tiles::cell_size` is a layer's cell in pixels: the map's `tile_size` for Tiled and for `add_tile_layer`, the layer's own `__gridSize` for LDtk, whose grid, int grid and cell counts follow it (`__cWid` and `__cHei` must match the level's pixels over the grid). The map's `tile_size` and `size` come from the bottom tile layer; a level with only entity layers uses `defaultGridSize`. Tiles outside the level (auto-tiles of stamps reach past the edge) are dropped; tiles stacked in a cell come in drawing order and the last wins. IntGrid layers hold their auto-tiles as `grid` and `collides` is true, every other layer's is false. Parallax is `1 - parallaxFactor`. Entity `position` is the top-left (`px` less pivot times size), rotation 0, `class` and `name` the entity identifier, `id` the iid. Field values by `__type`: Point is a `Class` "Point" with `cx` and `cy`, Tile a `Class` "Tile" with `tileset` (identifier), `x`, `y`, `w`, `h`, EntityRef `Object(iid)`, enums `Enum { ty, value }`, arrays `List`; an unset field (null value, or an unset reference) is left out, and null items of an array are skipped. Worlds: a single-world project has one `WorldLayout` named "World" and levels whose `world` is `None`; with multi-worlds each world has its name. A `Neighbour::level` indexes the same world's `WorldLayout::levels`. Linear layouts (`LinearHorizontal`, `LinearVertical`) write no positions, so levels follow one another from the origin, each after the last one's width (or height) plus LDtk's own spacing of 48 px (`World.reorganizeWorld` in LDtk's source; the JSON docs only say "one after the other"). Parallax `1 - factor` is what LDtk's editor shows (it shifts a layer by camera times factor); `parallaxScaling` has no counterpart and is ignored. Level backgrounds images are not loaded; `TileMap::background` is `__bgColor`, else the level's `bgColor`, else the project's `defaultLevelBgColor`.
