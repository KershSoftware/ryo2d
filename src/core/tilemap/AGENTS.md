# AGENTS.md - Tilemap Module

Sub-project 6a replaces the old tilemap module. Design: `docs/specs/2026-10-29-tilemap-design.md`. What exists so far is the data model, the Tiled (JSON and XML) and LDtk loaders, maps spawned as entities and edited at runtime, their layers drawn through the world batch: tile layers from cached chunks (y-sorted ones row by row among the entities), image layers and tile objects as sprites (render module notes, Tile chunks, and Image layers and tile objects), and their tiles colliding and casting 2D shadows; the rest arrive task by task.

## What exists

- `tile.rs`: `Tile` (tileset index, id, `TileFlip`) and `TileFlip` (H, V, D bits as Tiled stores them; `rotated_cw` uses Tiled's table).
- `property.rs`: `PropertyValue` and `Properties` (insertion-ordered, typed getters; `int` accepts a whole float, `float` accepts an int).
- `tileset.rs`: `Tileset` (an `Asset`; atlas or collection; per-tile `TileData` with shapes, animation, probability; `WangSet`s) and `URect`, the engine's own texel rectangle (glam has none).
- `grid.rs`: `TileGrid`, a dense layer of 4-byte cells (0 empty; flips in bits 28..=31, tileset in 20..=27, id + 1 in 0..=19) cut into `CHUNK_SIZE` (32) chunks. Edits mark chunks dirty; `drain_dirty` hands each changed chunk out once in row order. A new grid has no dirty chunk. A tile that does not fit a cell (tileset over 255, id over 1,048,574) is refused by `set`.
- `map.rs`: `TileMap` (an `Asset`) of `MapLayer`s (`LayerInfo` plus a `LayerKind` of tiles, objects or an image) over `TilesetSource`s (asset handle or embedded `Arc`). `IntGrid::get` returns `None` for 0 as well as outside.
- `spawn.rs`: maps as entities. `MapRoot` (a `TileMap` handle, or an LDtk project and a level by identifier or iid; class tiles, IntGrid collision overrides, collision off, base z) on an entity whose `Transform` places the map's top-left corner. `spawn_maps` (`PreUpdate`, chained after the asset pump) lands each ready map whole (below), or sends `MapEvent::Failed` once per failure. `map_asset` resolves a root to its `TileMap`, `root_map` the same from the stores a system holds.
- **A map lands whole.** When a root's asset (and its tilesets) is ready, `spawn_maps` copies the asset's layers, the root's settings, the class-tile table and the tilesets' `ShapeSource`s and stamps into a `LandingJob` for its `Worker`, and marks the root `MapLanding { job }`. The job takes the class tiles out of the grids' copies (marking every chunk dirty), and works out the colliders (`collision::prepare`: every grid classified, traced and packed, the packs' Rapier shapes built) and the shadows (`occluders::prepare`: every chunk's chains) for the layers as they will spawn, layers named by their place (entities are stand-ins until they spawn). When it comes back (polled every `spawn_maps`), `land` spawns the layers and the objects' entities, inserts `MapIds` and `MapLayers`, puts the colliders (with their `Traced`) and the shadows on (`collision::land`, `occluders::land`: entities relinked by place), then gives the objects their components (observers run), spawns the class tiles, and sends `MapEvent::Spawned`: all in one frame, and the fixed step that frame (or the next) builds the parts from the traces before physics steps, so a body an object observer or a `Spawned` reader puts on the map lands on its ground (`a_body_on_a_map_reported_ready_never_falls_through`). Until then nothing of the map is in the world but its root, and `MapsView` reads nothing. A root disabled, despawned or given another root while its landing is out drops the result (`root_discarded` takes `MapLanding` too). The arrival looks roots up with `Allow<Disabled>`, so a disabled one loses its `MapLanding` and is worked out again once enabled (`a_root_disabled_while_its_landing_is_out_lands_once_enabled`; looked up with the default filter, its result was dropped with `MapLanding` left on, and it never landed). A job that panicked is logged and worked out on the main thread. If that panics too, the root gets `MapFailed` holding `landing_stamp` (the versions of its map or LDtk project and of each tileset asset the map uses) and `MapEvent::Failed` is sent once; it is not tried again until one of those versions changes (`a_landing_that_always_panics_is_reported_once_and_not_retried`; before, it was sent again every couple of frames). A test's map makes its landing panic with the `PANICKING_LANDING` property (test builds only). On the web (no threads) the job runs where it is sent, so the map lands in the frame its asset is ready. Layer flags set on layer entities (`collides`, `occludes`, properties) can only change after the landing, through the systems' rebuild path.
- `kinds.rs`: what a cell is, for collision or light, pure so a landing job runs it off the main thread: `ShapeSource` (a tileset's tiles with shapes, read once: each tile's drawn size and shapes, the tileset's offset; `sources` for a map's tilesets), `placed`, `classify` and `tile_kind` (by `Purpose`), `intgrid_table`, the ranked union `over`, `Tracked` (a group layer's last-read chunk versions and IntGrid kinds) with `changed_chunks`, `TilesetStamp`, and the `Layers` and `Stores` query aliases both systems use.
- `jobs.rs`: `Worker`, one thread for `spawn_maps`' landings (started with its first job, named `ryo2d map builder`) taking boxed jobs and handing back each one's id and result (`None` for a job that panicked); where no thread starts (the web) a job runs where it is sent.
- `collision.rs`: `sync_map_colliders` (`FixedSet::Movement`, before physics' `rebuild_tile_colliders`, so an edit made in `update` collides in that step; `register_tilemap_systems` in `mod.rs`) keeps each spawned map's colliding tile layers in a `TileColliders`, with the crate's `MapCollision` on the map entity. Colliding layers (`LayerInfo::collides` on a root with collision) group by cell size, offset and collision material: the group of the map's `tile_size`, no offset and the map's material unions into one `TileColliders` on the map entity, any other gets its own on its first layer's entity (whose `Transform` carries the offset), so two colliding layers meet without a seam unless they differ in one of the three. A cell takes the strongest kind across its group (`Solid` > `Shape` > `Slope` > `OneWay`); on a tie (two shapes, two slopes) the upper layer's wins. An IntGrid layer collides by its values (`intgrid_table`: an override by value, else by name, else the default names `solid`, `one_way`, `slope_*`, all ignoring ASCII case), any other by its tiles' shapes not marked `occluder`, placed where the tile draws (`placed`, Task 7's rules: a tile stands on its cell's bottom edge from the left, `tile_offset` moves it, flips turn it: diagonal, then horizontal, then vertical) and classified (`classify`): a full-cell rectangle `Solid` (`OneWay` if one-way), three cell corners `Slope` (the right angle opposite the corner left out), anything else a `Shape` added once per distinct geometry (`ShapeKey`, points on a 1/46,080 tile grid). A tile with solid and one-way shapes collides with its solid ones only (`CellShape` has one `one_way`). Each tile's kind is worked out once per group (`kinds`), from the map's `ShapeSource`s. Material: the properties `collision_layer`, `collision_mask` (a 32-bit int: -1 is every bit), `friction` and `restitution`, a layer's over its map's over `TileColliders`' defaults (an ice layer saying `friction` 0 is a grid of its own); a wrong type warns once a map per layer and property, and what is under it counts.
  - **The first build** comes with the map's landing (`prepare`, `land`; see `spawn.rs` above): every grid on its target with its `Traced`, so physics only spawns the parts and inserts their shapes as built. Physics packs a grid's outlines by chunk (a part for the loops starting in each 32-cell chunk; physics module notes, Packing), so a map's part count follows its area, not its islands. Whatever builds the grids again after that (enabled again, a layer's flags, the tilesets or the overrides changed) builds at once on the main thread. The landing frame of a 256 x 256 four-layer map adds about 0.03 ms for terrain and about 0.2 ms for 1,024 separate islands in 64 parts (`spawning_a_256_map_adds_under_half_a_millisecond_to_any_frame`, ignored, release, timed after a warm-up since a process's first second runs slow; a part per island took about 1 ms, nearly all of it Rapier taking in the colliders).
  - **What changed:** every step the group's layers' `TileGrid::version` is compared with the last seen (never `drain_dirty`, which one consumer would empty for the others); for a layer that moved, each chunk whose `chunk_version` moved is classified again across the group and `TileColliders::set` is called only for cells whose kind changed, so physics' loop-local rebuild stays local. An IntGrid layer whose names (seen when `TileLayerData` changes) now give other kinds re-reads all its chunks. A change of what the grids are built from (the colliding layers, their entities, cell sizes, offsets, materials and sizes, whether each has an IntGrid, the map's tile size, the overrides, a tileset's content version or embedded `Arc`) builds every group again (new `TileColliders`, which physics builds whole). An idle step costs a look at each map's layers, tilesets and properties (about 0.1 µs a map in release); an edit's step about 18 µs for one chunk of four 1024-wide layers (`one_tile_edit_sync_timing`, ignored).
  - **Disabled, despawned, root gone:** `Disabled` does not reach the layers, so a disabled map's sync takes away every `TileColliders` it put on (the map's and its layers'), and enabling builds them all from the tiles as they then are. A despawned map takes its colliders with it (the map-level parts are its children, a layer-level grid's are its layer's). A map whose root is put over or taken away (no `MapLayers`, or no `MapRoot`) loses its grids and `MapCollision`. A disabled layer entity does not collide. A map with collision owns the `TileColliders` on its entity: one a game put there is replaced.
  - A layer's visibility does not matter: a hidden layer (a common collision-only layer) collides, and occludes as its flags say.
  - **Too large:** a group over 8192 cells a side (the loaders take up to 2^26 cells a layer) gets no `TileColliders`, and the map warns once naming its layers.
  - IntGrid values are followed through their layer's grid versions: a game writing `TileLayerData::intgrid` values directly (there is no IntGrid edit yet) sees them collide in the chunks whose tiles change next, or everywhere after `grid.mark_all_dirty()`.
- `occluders.rs`: `sync_map_occluders` (`PostUpdate`, before `PostUpdateSet::Transforms`) keeps each map's shadows, with the crate's `MapShadows` on the map entity. A layer occludes as `LayerInfo::occludes` says, else as it `collides` (the root's `without_collision` does not change it); occluding layers sharing a cell size and offset occlude as one, each cell the strongest kind across them (collision's `over`). A tile occludes with its shapes marked `occluder`, else its collision shapes (one-way ones too), as one solid shape placed as collision places it (`Purpose::Occlusion` in `kinds.rs`); an IntGrid's `Solid` cells whole and its slopes as their half cell (a one-way cell has no area to occlude with).
  - **Boundary chains, not rectangles:** an occluder whose edge touches another's casts that edge's shadow through the other's lit art (a black wedge at full strength, measured headless), so the occluders are the boundary of what occludes: `physics::Boundary` reads the tile colliders' outline units (each cell's inside, the borders left of and above it; shapes fitted to their cells on the outline grid; edges two cells share cancel, partial overlaps too), reversed to lighting's winding. Each chunk owns the units of its cells and, where it reaches them, the grid's right and bottom borders, so the chunks' edges together are the boundary with nothing twice, and nothing at a chunk border. A chunk's edges are chained greedily (`chains`: from the points more edges leave than reach, then round the loops left; straight runs merged) into `LightOccluder2D::chain`s, each a child of the group's first layer marked `MapOccluder { chunk }` (prelude), its entity at the centre of its corners' box (lighting's reach test reads the entity's translation), so a chain spans one chunk at most. Shapes are clipped to their cells, as collision clips them.
  - **The first build** comes with the map's landing: `prepare` works out every chunk's chains off the main thread, and `land` spawns them all (`World::spawn_batch`) as the layers spawn. After that a rebuild (enabled again: a disabled map keeps its `MapShadows`, emptied; its layers, tilesets or overrides changed) is at once on the main thread.
  - **Edits:** the group's layers' chunk versions, as collision's (`changed_chunks`); a moved chunk's chains are despawned and built again, every other chunk's kept. A chunk's borders read the column left of it and the row above, so each chunk keeps the kinds of its right column and bottom row (`Sides`): when they change, the chunk right of it or below it is built again too, row by row in the same pass. A disabled map or layer, a layer that stops occluding, a map whose root went, or a change of the layers, tilesets or overrides takes every chain down (built again when it applies).
- `edit.rs`: `LayerRef` (name or index), finding a layer entity, cell reads and edits, world/cell conversions. `view.rs`: `MapsView` (`ctx.maps()`), the public face of `edit.rs`.
- `wang.rs`: `MapsView::set_terrain` (Wang auto-tiling) and `WangSet::best_tile` / `color_index` (public, for procgen). Each `WangTile` carries its tile's probability, copied at load (`build_tileset` builds the sets after the tiles; both readers share it). Painting sets the cell's corners (corner set), edges (edge set) or all eight (mixed) to the colour; the cell and every cell sharing one of those positions that holds a tile of the set pick again, reading each position from the paint, else from the neighbours outside the painted reach, else from the cell's own tile, and edit through `edit::set_tile`. A fit is exact on the kind's positions (no nearest-match fallback); a miss keeps the cell's tile and warns once per set name (`WangWarned`). Equal fits are weighed by tile probability times its colours' and drawn by a hash of the cell. Cells holding no tile of the set (empty, another set's, a class tile) are left alone; flips are ignored when reading a tile's colours. The fixtures `wang-grass` were painted by Tiled's own brush: `tests/fixtures/tilemap/tiled/scripts/paint-wang.js`.
- `padded.rs`: each tileset's tiles copied into power-of-two cells of a padded `Image` of its own (edges extruded, so no filter or mip level reads a neighbour). A cell's side is `next_power_of_two(max(2 * T, T + 8))`, T the largest tile's longer side (R10): mip level k samples only a tile's own cell while `2^k` is at most the cell's room past the tile, which is then at least T (every level a tile drawn a pixel wide or more uses) and at least 8 (every level of an atlas page). Power-of-two tiles from 8 px keep cells twice their side; tiles just under one (14, 15, 30 px) take the next power up, and tiles of 30 or 14 px read their neighbours zoomed out with the old `T + 2` rule (`no_seams_at_any_zoom_or_subpixel_camera`'s odd-size legs). The cells sit `margin` texels in from every side (`cell - 8`): with the 8 texel border a texture puts around an image (`atlas::BORDER`), every cell starts on a multiple of its side and the texture's sides are whole cells. A padded image over 256 px gets a texture of its own with every mip level, and the GPU sizes each level by rounding down and spreads it over the whole texture: without the margins its levels from the fifth (16 texels a texel) mixed neighbouring cells into a tile, and those of a texture whose side was not a multiple of the level's texel drifted off the full-size one (`no_seams_at_any_zoom_or_subpixel_camera`, zoom 0.1). Known limit: in a texture of its own, a tile drawn under a pixel wide reaches levels past the cell's room, and from one texel a cell the levels mix cells. `PaddedLayout` says where each tile and animation frame sits; `PaddedTilesets` makes one per tileset, again when the tileset or an image of it changes (in place, keeping the handle), and frees those a round of `get`s did not ask for. An animated tile's frames take consecutive cells after the static ones; unequal frame times repeat frames to a common beat (past 128 cells, the mean time). `render/tiles.rs` turns a chunk into instances in layer-local pixels (lane layout in its module docs), and its `TileDrawer` draws spawned maps' tile layers: a map's tilesets padded each frame it exists (a disabled map's too, so its images stay; a disabled map draws nothing, `Disabled` not reaching its layers), hidden layers skipped, each visible chunk built once into the batch's chunk store and drawn at the layer's interpolated transform. A layer entity's own `RenderLayers` replace the map's for what it draws. Each padding gets a `serial` never given before, which the chunks' look stamp includes, so a tileset padded again rebuilds the chunks drawn from it. `TileGrid::chunk_version` and `version` stamp every change from one process-wide counter (R8 as amended), so a version never repeats, across grids and clones too: a layer whose `TileLayerData::grid` is swapped for another, even one filled the same way, redraws. A fill or `mark_all_dirty` is one change, one version; consumers keep their last-seen versions.

## Gotchas

- `tiled/`: Tiled's formats as registry assets. `raw.rs` holds what a file says (serde structs named as Tiled's JSON names them; `xml.rs` fills the same ones from TMX, TSX and TX, so every non-zero default is an `Option` and `build.rs` owns the defaults), `data.rs` decodes gids and layer data (CSV, base64, gzip, zlib, zstd via `ruzstd`, all bounded by the layer's cell count), `build.rs` turns raw into `TileMap` and `Tileset` and holds the checks, `json.rs` the `TiledMapLoader` (`.tmj`, `.tmx`) and `TiledTilesetLoader` (`.tsj`, `.tsx`), picking the reader by extension, `objects.rs` the objects of object layers and templates, `wang.rs` Wang sets, `project.rs` the Tiled project file and the property resolution (`Props::read`, `resolve_properties`).
- A path written in a file joins that file's folder; the registry normalises it and refuses one leaving the asset root. An inline tileset's paths resolve against the map's folder.
- External tilesets are dependencies and are not loaded while the map loads, so a gid is matched to a tileset by `firstgid` alone. The ids each tile layer uses are noted in `TileMap::used_ids` and measured against the tilesets in the map's `check`; the atlas image against the declared tiles in the tileset's `check`.
- Group layers flatten: offset adds, opacity and tint multiply, parallax multiplies, visibility ands, a non-normal blend passes down. Layer ids stay as written; a layer without one gets the next free id.
- Limits, each a load error naming the place: 1<<26 cells a layer or map, 256 tilesets a map, 1,048,575 tiles a tileset. Unsupported until 6b: isometric, staggered, hexagonal and oblique maps and infinite maps; layer blend modes other than normal, add, multiply and screen.
- A tileset's `tileoffset` is kept as `Tileset::tile_offset`.
- Objects: `MapObjectData::position` is always the top-left corner of the object's rectangle in map pixels and `rotation` (radians, clockwise on screen) turns it about that corner. Tiled rotates about the object's own position, which for a tile object is the tileset's `objectalignment` point (bottom-left by default), so a tile object's position is moved to where its top-left corner ends up. A map cannot look inside an external tileset while it loads, so a map with tile objects `cx.read`s the `.tsj` or `.tsx` for its `objectalignment` (`objects.rs::read_alignment`). Ids are Tiled's, as strings; object-reference properties are `PropertyValue::Object(id)`. Fields of `RawObject` an instance of a template can override are `Option`s: the instance starts as the template's object, its own fields win and properties merge by name. A template tile's gid is relative to the template's tileset, matched to the map's by resolved path (a tileset the map lacks is a load error). Templates load from `.tj` and `.tx`. The XML reader (`roxmltree`) leaves an absent attribute `None` and never defaults it, writes class members and numbers as the JSON would hold them, and bounds group nesting by `build.rs`'s `MAX_DEPTH`; its errors read `line L, column C: what`. An XML fixture's properties must be in Tiled's JSON order (alphabetical) for the twin test, which compares every `xml/` fixture with its JSON export field by field.
- The Tiled project (`project.rs`): `[tilemap] tiled_project` in Ryo.toml, `EngineBuilder::tiled_project` over it, else `project.tiled-project` at the asset root if there is one (a configured file that is missing is a load error). The loaders are registered with the path (`with_project`) after `insert_registry`'s default ones. It is read with `cx.read`, so saving it loads the maps again. `Props::read(place, raw, class)` resolves a thing's properties: written values lie over the class member's default, members it omits take the default, nested classes layer (instance over the member's default over the nested class's own), enums read by name (flags as a `List`). Without the project or the class, what is written is kept and `engine_warn!` names the class once per file.
- Wang sets load as written (`wangid` is clockwise from the top, 0 for no color); colors and tile ids are checked.
- `LayerInfo::occludes: None` means "as `collides`"; `lit` defaults to true.
- Spawned maps: the map entity gets a child per layer (`MapLayerRef`, the layer's `LayerInfo` as a component, a `Transform` at the layer's offset; `TileLayerData` for a tile layer, `ImageLayer` for an image layer), plus `MapIds` (objects by id) and the crate's `MapLayers` (layer entities by index). `TileLayerData` is the entity's own copy of the grid and IntGrid, with every chunk marked dirty at spawn (a new `TileGrid` has none) so the chunk renderer builds each once. Objects are children of their object layer: `MapObject` with a `Transform` at the centre of the object's rectangle (its point; a polygon's or polyline's origin, Tiled giving those no size), turned by its rotation, polygon points relative to it; a tile object keeps its `tile`, and a hidden object spawns with `visible: false` (games use hidden markers; drawing skips it). Tiles of a class the root registers are taken out of the copied grid and spawn as `MapTile` children of their layer at the cell's centre in the layer's cell size, listed by cell in the layer's `LayerTiles` (crate). The objects' entities are spawned and `MapIds` inserted before the `MapObject`s go on, so an `Add<MapObject>` observer can resolve references.
- Game observers run as each part arrives and may despawn the map, a layer or an object before its turn: the spawn checks each is alive (`get_entity_mut`, never `entity_mut`), skips what is gone, and stops (no `Spawned`) once the map is gone. Every child is spawned as `(Transform, ChildOf(parent))` first and its observed components inserted after (`child_of`): bevy runs `Add` observers before `ChildOf`'s insert hook, so an observer that despawned the parent of a child spawned whole would orphan it and fail the hook's queued `Children` update on the gone parent.
- Runtime edits place class tiles too: `set_tile`/`fill` with a tile whose class the root registers spawn a `MapTile` (the grid cell cleared) instead of writing the grid; a class tile on a cell any edit touches is despawned first (the same tile again changes nothing). A plain `fill` takes the class tiles in its region through `LayerTiles` and fills the grid in one go; a class-tile `fill` goes cell by cell. `tile()` reads the grid, so a cell holding a class tile reads `None`. `MapObject::reference` reads `PropertyValue::Object(id)`, treats Tiled's unset `"0"` (and an empty id) as none, and checks the entity is alive (no bookkeeping system: a despawned object just stops resolving).
- A map waits while its asset (or, for a map built in code, a tileset asset it names) loads; one despawned meanwhile (a scene's `SceneCleanup::WORLD`) or no longer a `MapRoot` is not in the query and spawns nothing; a disabled one waits until enabled. A failure is reported once per `Arc<AssetError>` (the registry shares one per failure), and a missing LDtk level once per project version; a failed map whose file is saved fixed spawns. `MapRoot`'s `on_discard` hook takes down a spawned map's layers (and `MapIds`, `MapLayers`, the reported failure) when the root is replaced or removed, so a new root spawns afresh.
- `MapsView` finds layers through `MapLayers` (by index, or the first by name), returns `None`/`false`/0 for a map not spawned, a missing layer, a non-tile layer or a cell outside, and marks `TileLayerData` changed only when an edit changed a cell. World/cell conversions take a layer (R7: cell size is per layer) and walk the `Transform`s of the layer and its ancestors as they are now, not `GlobalTransform`, so a map moved this frame converts before propagation; `world_to_cell` gives cells outside the layer too, and `None` for a layer scaled to nothing.
- `ldtk/`: LDtk 1.5.x projects (`.ldtk`) as `LdtkProject` assets, one `LdtkLevel` per level with its `TileMap`. `raw.rs` holds what a file says (LDtk's JSON names), `build.rs` the conversion and the checks (reusing `tiled::build`'s `fail`, `join`, `load_dep`, `check_tileset`, `check_used_ids`), `mod.rs` the types and `LdtkLoader`. A newer `jsonVersion` than 1.5 is a load error naming both versions; older loads. Tilesets are shared: `LdtkProject::tilesets` in definition order, each level's map embeds them all (a tile's `tileset` is the definition's index). A tileset with no `relPath` (LDtk's built-in icons) is a `Collection` with nothing to draw. `.ldtkl` levels are read with `cx.read` (saving one loads the project again); paths join the project's folder.
- LDtk levels: `layerInstances` list the top layer first, so layers are reversed (layer 0 draws first). `LayerKind::Tiles::cell_size` is a layer's cell in pixels: the map's `tile_size` for Tiled and for `add_tile_layer`, the layer's own `__gridSize` for LDtk, whose grid, int grid and cell counts follow it (`__cWid` and `__cHei` must match the level's pixels over the grid). The map's `tile_size` and `size` come from the bottom tile layer; a level with only entity layers uses `defaultGridSize`. Tiles outside the level (auto-tiles of stamps reach past the edge) are dropped; tiles stacked in a cell come in drawing order and the last wins. IntGrid layers hold their auto-tiles as `grid` and `collides` is true, every other layer's is false. Parallax is `1 - parallaxFactor`. Entity `position` is the top-left (`px` less pivot times size), rotation 0, `class` and `name` the entity identifier, `id` the iid. Field values by `__type`: Point is a `Class` "Point" with `cx` and `cy`, Tile a `Class` "Tile" with `tileset` (identifier), `x`, `y`, `w`, `h`, EntityRef `Object(iid)`, enums `Enum { ty, value }`, arrays `List`; an unset field (null value, or an unset reference) is left out, and null items of an array are skipped. Worlds: a single-world project has one `WorldLayout` named "World" and levels whose `world` is `None`; with multi-worlds each world has its name. A `Neighbour::level` indexes the same world's `WorldLayout::levels`. Linear layouts (`LinearHorizontal`, `LinearVertical`) write no positions, so levels follow one another from the origin, each after the last one's width (or height) plus LDtk's own spacing of 48 px (`World.reorganizeWorld` in LDtk's source; the JSON docs only say "one after the other"). Parallax `1 - factor` is what LDtk's editor shows (it shifts a layer by camera times factor); `parallaxScaling` has no counterpart and is ignored. Level backgrounds images are not loaded; `TileMap::background` is `__bgColor`, else the level's `bgColor`, else the project's `defaultLevelBgColor`.
